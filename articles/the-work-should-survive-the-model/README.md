# The Work Should Survive the Model

Article Zero of four. This is the non-technical product argument for aimee: what
is different, where it is useful, how a buyer should test the investment and
what the product's uniqueness claim includes. Its central measured case is a
failure learned by local Qwen that changed later Luna and Terra work, including
a Terra hidden-grade completion crossover.

## Claim boundary

The article claims that, as of 2026-08-27, the author has found no other
available product that closes the same full organizational learning loop in one
open-source system available as a managed cloud service or self-hosted.

It does not claim novelty for persistent memory, model routing, code search,
agent workflows, access control, audit logs or self-improvement in isolation.

It makes three bounded economic claims. In an eight-task paired coding run,
Aimee reduced provider-recorded billable token units per passing task by 22.0
percent while the pass count rose from five to six. Valuing the preserved token
categories at the published GPT-5.6 Sol API rates gives a 21.1 percent lower
price-equivalent bill per passing task. In a separate ungraded 50-task run,
delegation reduced frontier-model tokens by 58.6 percent. In three matched
large-codebase failure pairs, Aimee reduced local Qwen consumption from
1,819,904 to 1,199,552 tokens, a 34.1 percent reduction. Neither condition
solved any task, so that result establishes failure-cost containment rather
than a capability increase.

The cross-model pilot has one task and one run per arm. It establishes an
observed behaviour and completion crossover, not a population effect. Rakuen's
current production use is a first-party operator statement. Legal, accounting,
software and other professional fields are the intended scope, not a claim of
current deployment or measured efficacy in each field.
